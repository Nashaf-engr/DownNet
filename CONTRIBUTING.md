# Contributing to DownNet

Thank you for your interest in contributing to DownNet! We welcome contributions from the community.

## Getting Started

1. Fork the repository
2. Clone your fork: `git clone https://github.com/yourusername/DownNet.git`
3. Create a feature branch: `git checkout -b feature/your-feature-name`
4. Make your changes
5. Commit your changes: `git commit -am 'Add some feature'`
6. Push to the branch: `git push origin feature/your-feature-name`
7. Submit a pull request

## Development Setup

Follow the setup instructions in README.md to get the development environment running.

## Code Style

- **Python**: Follow PEP 8 guidelines
- **JavaScript/React**: Use ESLint with the provided configuration
- **CSS**: Use consistent naming conventions (BEM recommended)

## Testing

- Write tests for new features
- Ensure all tests pass before submitting a PR
- Run: `npm test` (frontend) or `pytest` (backend)

## Commit Messages

- Use clear, descriptive commit messages
- Start with a verb: "Add", "Fix", "Update", "Remove"
- Example: "Add support for Instagram Reels downloading"

## Pull Request Process

1. Update README.md with any new features
2. Ensure all tests pass
3. Update CHANGELOG.md
4. Request review from maintainers
5. Address feedback and re-request review

## Reporting Bugs

- Use GitHub Issues to report bugs
- Include steps to reproduce
- Include screenshots if applicable
- Include your environment (OS, browser, versions)

## Feature Requests

- Use GitHub Discussions for feature requests
- Describe the use case
- Explain why this feature would be useful

## Code of Conduct

Be respectful and inclusive. Discrimination, harassment, or abuse will not be tolerated.

## Questions?

- Open an issue with your question
- Check existing issues/discussions first
- Join our community Discord (if available)

Thank you for contributing!
